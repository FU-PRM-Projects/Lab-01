# PaperChat native package

This local Windows FFI plugin owns the Rust crate and all generated bindings. The package/crate name remains `lab_05_rust` so the DLL name stays stable.

- `lib/paper_native.dart`: public entry point (`initializeNative`, PDF and vector types).
- `rust/src/api/pdf_parser.rs`: `pdf-inspector` extraction and page-aware chunking.
- `rust/src/api/lance_store.rs`: a LanceDB table holding each chunk's vector alongside its metadata and text, with exact cosine search, page lookups, delete-by-document and compaction.
- `lib/src/rust/` and `rust/src/frb_generated.rs`: generated by flutter_rust_bridge.
- `windows/`: Cargokit wiring, using the package location rather than a fixed number of parent directories.
- `cargokit/`: upstream vendored build support. Retain its scripts and license together; it is not application code.

## Regenerate the bridge

From the repository root, with Flutter/Dart and Cargo on PATH:

```powershell
cargo install flutter_rust_bridge_codegen --version 2.13.0 --locked
Push-Location packages/paper_native
try {
  flutter pub get
  flutter_rust_bridge_codegen generate
} finally {
  Pop-Location
}
```

The Rust dependency, Dart dependency, and generator are pinned to **2.13.0**. `lancedb` is pinned to **0.39.0 with the `remote` feature**, which is not optional: without it the crate fails to compile, because `job.rs` constructs an `Error::Http` variant that is `#[cfg(feature = "remote")]`. Version 0.37.1 predates that bug but pins `time = "=0.3.47"`, which breaks `lopdf 0.44` (required by `pdf-inspector`), so downgrading is not an option either. Building also needs **`protoc`** on `PATH` — the `lance-*` build scripts run `prost_build`; install it with `winget install --id Google.Protobuf -e`, or set `PROTOC` to its full path. The config uses Dart `int` for the Windows bridge, eliminating application-side BigInt and Uint64 buffer conversions. Regeneration may emit conditional web files; only Windows is registered as a supported plugin platform.

Normal Flutter builds compile and bundle Rust automatically. For Flutter native service tests, build the standalone DLL first:

```powershell
cargo build --release --locked --manifest-path packages/paper_native/rust/Cargo.toml
flutter test --tags native
```

`initializeNative` takes an optional `libraryPath`, which the native tests use to load the freshly built DLL by relative path. Production initialization passes nothing and loads the bundled DLL using the generated bridge loader.

References: [flutter_rust_bridge/Cargokit](https://cjycode.com/flutter_rust_bridge/manual/integrate/cargokit), [lancedb](https://docs.rs/lancedb/latest/lancedb/).
